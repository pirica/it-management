# AGENT_NOTES.md - Public booking portal

## 1. Purpose

Guest-facing hotel listing and booking under `/it-management/booking/`. Uses ITM `config/config.php` (MySQLi) and `includes/itm_hotel_booking.php`.

**Canonical doc:** `docs/BOOKING.md` (architecture, flows, admin map, review, troubleshooting).

`bootstrap.php` defines `ITM_HOTEL_BOOKING_PUBLIC_PORTAL` before `config.php` so global employee login is skipped for this tree.

## 3. Auth

- **Browse and book:** no portal login. Guest details (name, email, phone) are collected on `rooms/room-single.php` and stored via `customers` + `hotel_bookings`.
- **Manage booking:** `users/bookings.php` — last name + **guest confirmation code** (`hotel_bookings.guest_confirmation_code`, opaque 10-character code — not sequential `hotel_bookings.id`) + **auth2** (12-character code with uppercase, lowercase, numbers, and symbols on new bookings; legacy 4-digit PINs are retired via backfill). Verified by `itm_hotel_booking_fetch_for_guest_manage()`; after PIN match the portal emails a **6-digit OTP** (`itm_hotel_booking_portal_manage_otp_issue()` / `_verify()`) before showing or cancelling a stay. Lookup failures and OTP issue failures share one generic message (`itm_hotel_booking_portal_manage_lookup_failure_message()`); the OTP step does **not** reveal a masked email. OTP verify uses a **separate** session + IP throttle (`itm_hotel_booking_portal_manage_otp_rate_limit_check()` / `_record()`, default 5 / 10 min) from lookup/cancel (`itm_hotel_booking_portal_manage_rate_limit_*`, default 12 / 15 min). OTP mail uses the reservation **hotel name** as the transactional template header (no gear icon), **From** address `hotel_booking_hotels.reservations_email` when set (`itm_hotel_booking_portal_reservations_email_send_options()` → `itm_send_email()` `from_email` / `from_name` overrides), and a **Manage my booking** footer link to tenant `hotel_booking_settings.urlmybooking`. Nav link, manage page title/H1, confirmation CTA, and hint anchor text use tenant **`portal_manage_booking_label`** (`itm_hotel_booking_portal_manage_booking_label_from_settings()`). Confirmation page and guest confirmation email share one manage hint via `itm_hotel_booking_portal_manage_booking_hint_html()` (**view or cancel** wording, last name + confirmation number + auth code; pass `settings` for configurable label).
- **Read reviews:** `hotel_booking_settings.reviews_url` (company default) and optional per-hotel `hotel_booking_hotels.reviews_url`; resolved via `itm_hotel_booking_resolve_reviews_url()`. Guest-rating bubble title/subtitle come from `portal_rating_title` / `portal_rating_subtitle` (tenant settings); **Read reviews ↗** when URL is set.
- **Hotel contact links (portal labels):** **Info** → `hotel_booking_hotels.contact_email` (general enquiries); **Email** → `hotel_booking_hotels.reservations_email` (reservations desk). Shown on the public hotel **Details** modal (`booking/js/hotel-booking-public.js`), **Change booking** modal (`hb_portal_render_hotel_action_links()` in `booking/includes/portal_checkout.php`), and manage-booking OTP mail footer (reservations address when set).
- Optional legacy: `hotel_booking_portal_users` and `auth/login.php` / `register.php` (not required for public flow).
- **CSRF:** Public auth POST handlers use `itm_require_post_csrf()` via `bootstrap.php`.

## 4. Entry points

- `index.php` — hotel list (all active `hotel_booking_hotels` across tenants); each card **From** price is **tax-inclusive cheapest room rate** (min BAR × highest active `plan_discount_percent`, usually Non-Refundable 10%, then + tourist tax for 1 adult); `HB_HOTELS` includes `cheapest_rate_label` / `cheapest_rate_plan_slug`; card image has gallery **‹ ›** arrows and **`1 / N`** counter when multiple photos exist; **Details** modal From* + label use the same cheapest offer
- `rooms.php` — **Step 1 of 4** Select a Room (progress line + H1 from `itm_hotel_booking_portal_checkout_step_heading_from_settings($settings, 1)`); enforces **`portal_bookable`**, stay rules (`itm_hotel_booking_portal_room_type_validate_stay`), **`cardQuoteOccupancy`** for fits/quote (`itm_hotel_booking_room_type_fits_occupancy()` — per-slice `min_adults` / `max_total_guests` + `max_extra_beds`, `child_max_age` band validation, connecting-unit combined capacity), mixed-type lock, `max_rooms_per_booking`, **connecting-room unit** banner + inventory (`itm_hotel_booking_portal_connecting_unit_*`), accessible/smoking filters (`data-accessible` from physical `hotel_booking_rooms.accessible_room` with type fallback / `data-smoking`); optional **accessible room** info banner when `portal_accessible_banner_enabled` — body from **`portal_accessible_room_banner_text`** (plain text); multi-room banner lists **guests per slot** (`occupancy_line_label` + split helper). When `portal_show_internal_rates` is on, Special rates modal lists internal **USE** / **COMP** (mutually exclusive with promo/special programs); `occupancy.internal_rate_code` flows into draft/checkout (`itm_hotel_booking_apply_internal_rate_to_breakdown()`). Portal date labels use tenant `portal_date_format` (DD/MM/YYYY, DD/MMM/YYYY, US, ISO) via `hb_portal_format_date_display()` + `hotel-booking-date-format.js` (`HB_SETTINGS.date_format`; regression `php scripts/verify_hotel_booking_portal_date_formats.php`). Room-type cards and hotel sidebar use gallery **‹ ›** arrows + **`1 / N`** counter; **View room details** modal shows policy badges and connecting copy. When `occupancy.rooms > 1`, guests **pick one room → Step 2 rate → return to Step 1** until every slot has a rate (**Room N of M** banner; `pick_room_id` redirects immediately to `select-rate.php` for that room; rated lines persist in checkout draft `room_lines` with per-line `portal_rate_plan_id`); multi-room lists show **rate name per room** (`hb_portal_room_line_rate_plan_label()` on reservation summary, select-rate **Your rooms**, Step 1 banner, and payment confirmation). Already-picked types with no remaining physical units show **Not available** on later slots; **card `/night incl. tax` quotes use per-slot occupancy** (`cardQuoteOccupancy` / `split_occupancy_for_room_line`) so prices do not double when `rooms=2`; connecting units sum split occupancy quotes across primary + partner BAR (`itm_hotel_booking_portal_connecting_unit_card_quote_nightly()`); list card **/night** uses cheapest plan discount (usually NR) stacked with special rates, tax-inclusive; strikethrough list = BAR+tax when `hotel_booking_settings.show_discount_strikethrough` is on (admin toggle; `HB_SELECT_ROOM.showDiscountStrikethrough`); `HB_SELECT_ROOM.cheapestPlanDiscountPercent` keeps JS `updatePrices()` aligned. Single-room stays keep the hotel photo sidebar card.
- `rooms/select-rate.php` — **Step 2 of 4** Select a Rate; re-validates `portal_bookable` + stay for the picked type. **Connecting units** (`occupancy.rooms = 1` + physical `hotel_booking_rooms.connecting_room_id` on the primary room): after primary rate, draft appends the fixed partner room (`itm_hotel_booking_portal_connecting_unit_append_unrated_pick`) and returns here for partner rate before Step 3 (`itm_hotel_booking_portal_checkout_required_room_line_count()` = 2). When `rooms>1`, each visit rates **one** room: **Your rooms** lists prior rated lines with occupancy + **selected-rate** per-night incl. tax; the **current** line has **no** list price — guest picks a rate here, then returns to Step 1 until `room_lines` count equals `occupancy.rooms`, then Step 3.
- `rooms/customize.php` — **Step 3 of 4**: when `portal_accessibility_options_enabled`, **Accessibility** select (None / mobility / hearing / visual / cognitive / other) with PEP link (`urlaccessibilitypep`) and required **I have read the PEP** checkbox when need ≠ None (`hotel-booking-customize.js` disables Continue until checked; server rejects POST without ack). **Special requests** shows pet controls only when all rated room types allow pets (`itm_hotel_booking_portal_draft_pet_policy()`); otherwise **No special requests available.** Pet daily fee comes from strictest line policy. Main column **room upgrade** card when `rooms=1` only (hidden when `occupancy.rooms>1`, draft has multiple `room_lines`, or `hotel_booking_settings.portal_hide_upgrade_upsell_when_multi_room` is on — default on); redirects to Step 1 when `rooms>1` but not every `room_lines` row has a rate (`itm_hotel_booking_portal_draft_all_rooms_rated()`); **View room details** opens the same room-detail modal as Step 1 (no Quick compare link); right column **Reservation summary** lists each `room_lines` row with per-room stay price when `rooms>1` (`itm_hotel_booking_portal_room_line_stay_charges()`). Shows **Subject to hotel approval** when `breakdown.requires_approval`. When the upsell checkbox toggles, `hotel-booking-customize.js` updates summary **room type name** (`baseRoomTitle` / `upgradeRoomTitle` from `hb_portal_reservation_room_title()` with optional room-number prefix when `portal_show_room_number_on_confirmation` is on) alongside totals; server render uses `display_room_title` when upgrade is already accepted in draft. Portal money symbol/position from `hb_portal_bind_money_settings()` + `hotel-booking-money.js`.
- Calendar JSON (`booking/calendar.php`) — passes occupancy; `itm_hotel_booking_hotel_calendar_month()` returns `prices_include_tax`, cheapest-plan day `price` (BAR × plan discount + tourist tax), `bar_excl_tax`, `rate_excl_tax`, `plan_discount_percent`, `cheapest_rate_plan_slug`, `cheapest_rate_label`. Select Dates summary label uses `cheapest_rate_label` (not hardcoded Best available rate).
- `rooms/room-single.php` — **Step 4 of 4** guest form: **requires an active checkout draft** with `occupancy` (POST without draft or without draft occupancy is rejected); locked check-in/out and occupancy from draft only; **charge re-resolves BAR, special-rate discount, and plan discount/surcharge from DB** via `itm_hotel_booking_portal_resolve_step4_charge()` — for multi-room stays each `room_lines` row is re-resolved with `itm_hotel_booking_portal_resolve_room_lines_pricing_from_db()` (session draft money fields are not trusted at INSERT); saves `hotel_bookings.portal_rate_plan_id` from resolved plan; creates one or more rows via `itm_hotel_booking_portal_insert_stay_bookings_locked()` (shared `auth2`, split payment across `room_lines`; **multi-room** uses one outer transaction with nested per-room `FOR UPDATE` locks; single-room keeps one transaction per row); new bookings get a 12-character **auth2** code; on success emails **guest** (`customers.email`) and **hotel reservations desk** (`hotel_booking_hotels.reservations_email`) via `itm_hotel_booking_portal_send_booking_confirmation_emails()` (same From/template pattern as manage OTP); email (`filter_var`) and phone (E.164 `+` country code) validated server-side. Compact step-4 layout (`.hb-checkout-page-step4`): side-by-side dates, compact special-requests card (including **The hotel cannot guarantee additional requests.** disclaimer), main-column **Total due**, full sidebar stepper + reservation summary; terms checkbox + **Book Reservation** in fixed `.hb-checkout-sticky-cta` (`form="hb-guest-form"`) so legal copy and CTA stay visible without scrolling.
- `rooms/payment.php` — confirmation after step 4: **Full name** (guest `customers.name`), **Number of nights** `(N night(s))`, **Guests** `👤 …` occupancy line, **Traveling with a pet** fee line when selected, read-only **room upgrade** card when `rooms=1` and upgrade accepted, **Special requests** + **Additional comments** (mirrors Step 3 customize), jsPDF download (**Save booking confirmation** — same card as screen, not print preview). Multi-room stays use **one guest-facing confirmation number** (lowest `hotel_bookings.id` in the auth2 group) and list **Your rooms** with type, **per-room rate name**, and per-room amount; internal sibling rows are not shown as separate confirmation IDs. Occupancy and customize fields stored in `hotel_bookings.notes` (`Occupancy: rooms=…`, `Room upgrade:*`, `Traveling with pet: yes`, etc.). Confirmation PDF is a rasterized card (html2canvas) plus a **clickable PDF `/URI` annotation** over the inline **Manage my booking** hint (`data-hb-pdf-manage-link`, `hotel-booking-confirmation-pdf.js` → `hbPdfAddManageBookingLink`); action buttons stay `.hb-pdf-exclude`.
- `rooms/confirmation-pdf.php` — session-scoped auto-PDF page (`data-hb-auto-pdf`) for the last booking in the same browser session.
- `calendar.php` — JSON nightly rates for Select Dates modal (check-in + optional check-out range; single check-in = 1 night). Modal month **◀ / ▶** controls; auto-advance when `daysLeftInMonth < hotel_booking_settings.calendar_month_advance_days_left` (seed **3**, admin editable; **0** = never; next month still prefetched).
- `users/bookings.php` — manage reservation (last name + reservation ID + **auth2** code + email OTP); lookup form uses **Back** (`hb-checkout-skip`); found booking renders the same confirmation panel as `rooms/payment.php` (room title via `hb_portal_reservation_room_title()` — includes assigned room number when `portal_show_room_number_on_confirmation` is on; **selected rate plan** (`hb_portal_booking_rate_plan_label()` from `portal_rate_plan_id` / notes), nights, guests, reservation notes, PDF + action buttons). Stay bar shows **Logout** (not **Edit stay**) linking to `auth/logout.php`. Cancelled stays show a **red** confirmation state (`Reservation cancelled`, status badge). Aside includes **Cancellation policy**, **Change booking** (modal with hotel name, directions, website, phone from `hotel_booking_hotels`), and **Cancel Booking** (future and present segments — check-out still in the future; sets the active segment status to `CANCELLED`; requires verified email OTP). `rooms/payment.php` confirmation aside also renders **Cancel Booking** for the session booking (last name + auth2 derived from the booking/customer record).
- `cancellation_policy/` — default HTML policy pages (`1_cancellation_policy.html` … `4_cancellation_policy.html`) plus **`404.html`** (not-found fallback); URLs configurable per hotel in **Portal Rate Plans** admin module. **Not found path** is tenant-configurable in [Hotel Booking Settings](http://localhost/it-management/modules/hotel_booking_settings/index.php) (`portal_cancellation_policy_not_found_url`, default `cancellation_policy/404.html`). Guest modal and checkout links prefer **`cancellation-policy.php?company_id=&hotel_id=&slug=`** (`itm_hotel_booking_portal_cancellation_policy_guest_url()` / `itm_hotel_booking_load_cancellation_policy_html()` — DB HTML first, then seed file; missing plan/body → `itm_hotel_booking_portal_cancellation_policy_not_found_html()`). Each static page ends with a **Back** button (`history.go(-1)`), which is located outside the `<main>` element to prevent it from being loaded into the HTML editor when rate plans are updated.
- `auth/login.php`, `register.php`, `logout.php` (`logout.php` clears portal user session and returns to `index.php`)

## 5. Tenant

`hb_public_company_id()` picks welcome/chrome company from session or the first `hotel_booking_settings.public_portal_enabled` tenant (fallback company 1). **Browse/book hard gate:** `hb_company_public_portal_enabled()` / `hb_require_company_public_portal()` — [`rooms.php`](http://localhost/it-management/booking/rooms.php), [`calendar.php`](http://localhost/it-management/booking/calendar.php), [`rooms/select-rate.php`](http://localhost/it-management/booking/rooms/select-rate.php), [`rooms/customize.php`](http://localhost/it-management/booking/rooms/customize.php), and [`rooms/room-single.php`](http://localhost/it-management/booking/rooms/room-single.php) redirect (or JSON 403 for calendar) when that hotel’s company has the portal off. Home [`index.php`](http://localhost/it-management/booking/index.php) lists only hotels whose company has `public_portal_enabled`. Manage booking stays available for existing reservations. `hb_load_active_hotel_row()` resolves a hotel by `id` for rooms/calendar before the gate runs.

## 9. Portal step pricing (no hardcoded checkout amounts)

Per-hotel portal math is **not** hardcoded in `booking/*.php` or `booking/js/*.js`. Values load from `hotel_booking_hotels` via `itm_hotel_booking_portal_hotel_pricing()`:

| Column | Used for |
|--------|----------|
| `portal_breakfast_adult_price_per_night` | Breakfast rate plan add-on (adults) |
| `portal_breakfast_child_price_per_night` | Breakfast rate plan add-on (children); Step 2 info banner |
| `portal_child_nightly_supplement` | Extra per child on nightly room quote |
| `portal_extra_adult_supplement_percent` | % of base rate per adult above 2 per room |
| `portal_pet_daily_fee` | Pet checkbox add-on per night (Step 3 customize); shown as **Traveling with a pet** line on reservation summary, payment confirmation, and confirmation email when selected |

**Admin:** [Portal Rate Plans](http://localhost/it-management/modules/hotel_booking_portal_rate_plans/index.php) — **Portal step pricing** form (per selected hotel). Schema defaults match `itm_hotel_booking_portal_pricing_defaults()` when columns are unset.

**Room type calendar:** [Room Type Calendar](http://localhost/it-management/modules/hotel_booking_room_type_calendar/index.php) — date-range BAR overrides and stop-sell blocks per room type. Portal uses `itm_hotel_booking_resolve_room_type_nightly_bar()` for card/check-in display and `itm_hotel_booking_compute_stay_payment_dated_rates()` for multi-night checkout when `room_type_id` is on the checkout draft. Availability: `itm_hotel_booking_room_unavailable_for_stay()` (bookings + OOO/OOS + HSK maintenance + type blocks). Migration: `db/migrations/hotel_booking_room_type_calendar.sql`.

**Tourist tax** amount and **guest-facing labels** (tax line, incl.-tax copy, BAR/breakfast fallbacks, discount cap, default pet max kg) are company-level on `hotel_booking_settings` ([Hotel Booking Settings](http://localhost/it-management/modules/hotel_booking_settings/index.php)). **Breakfast child age band** for Step 2 copy is per hotel on the [Portal Rate Plans](http://localhost/it-management/modules/hotel_booking_portal_rate_plans/index.php) pricing form.

**JS:** `rooms.php` passes `portalPricing` + `pricingDefaults` on `window.HB_SELECT_ROOM` for live occupancy/rate recalculation (`hotel-booking-select-room.js`). Stay bar occupancy is interactive only when `hb_portal_render_stay_bar(…, ['occupancy_interactive' => true])` (rooms page); manage/confirmation/checkout steps render a read-only occupancy label (no inert button).

**Migration (existing DBs):** `db/migrations/hotel_booking_portal_hotel_pricing.sql` (destructive `hotel_booking_hotels` replace — back up before apply).

## 11. Portal UI copy (`portal_ui_*`)

Guest-visible micro-labels, errors, modal headings, filter names, confirmation copy, and manage-booking strings use **`portal_ui_*` columns** on four satellite tables (not `hotel_booking_settings` — InnoDB row-size limit). `itm_hotel_booking_settings_row()` merges satellite rows so templates still receive a flat `$settings` array.

| Layer | Contract |
|-------|----------|
| Registry | `includes/itm_hotel_booking_portal_ui_copy_registry_data.php` |
| Getter | `itm_hotel_booking_portal_ui_copy_from_settings()` |
| PHP templates | `hb_portal_ui_copy()` / `hb_portal_ui_copy_esc()` (`portal_chrome.php`) |
| JS | `HB_SETTINGS.ui_copy` + `hbUiCopy(key, fallback)` |
| Admin | [Hotel Booking Settings](http://localhost/it-management/modules/hotel_booking_settings/index.php) — Portal UI copy section cards |

Special-rate program labels, accessibility need options, and manage lookup failure text read the same registry via helpers in `includes/itm_hotel_booking.php` when `$settings` is passed. **Special-rate code fields** validate against `hotel_booking_special_rate_codes` (`itm_hotel_booking_portal_filter_occupancy_special_rate_codes()` on Step 1/2; AJAX `validate-special-rate-code.php`; invalid-code copy `portal_ui_step1_invalid_special_rate_code`). Codes are registered in [Booking Special Rates](http://localhost/it-management/modules/hotel_booking_special_rates/index.php).

**Gap copy (auth, dates modal hints, gallery/modal chrome, room-detail occupancy, payment empty state, PDF gate):** wired in the same release — keys such as `portal_ui_shared_modal_close`, `portal_ui_home_dates_*`, `portal_ui_step1_room_*`, `portal_ui_auth_*`, `portal_ui_confirm_payment_empty_*`. JS `hbUiCopy()` merges `HB_SETTINGS.ui_copy`, `HB_SELECT_ROOM.ui_copy`, and `HB_CUSTOMIZE_UPGRADE.ui_copy`. Migration: `db/migrations/hotel_booking_portal_ui_copy_gap.sql`; schema regen helper: `php scripts/apply_portal_ui_copy_gap_schema.php --apply`.

Removed legacy Colorlib template tree: `about.php`, `contact.php`, `services.php`, `404.php`, `config/config.php` (PDO), `includes/header.php` / `footer.php`, vendored `scss/`, `css/style.css`, jQuery/Bootstrap JS stack, `fonts/`, and the entire `admin-panel/` folder.
